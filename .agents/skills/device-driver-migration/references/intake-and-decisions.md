# 输入、证据与实现决策

## 开工所需输入

按任务读取实际存在的材料，不要求用户重复提供本地可发现的信息：

| 类别 | 最少输入 | 缺失时处理 |
|---|---|---|
| 新驱动 | 设备协议/API文档、目标语言、部署平台 | 可先建骨架和待确认表；不得编造命令或成功条件 |
| 旧驱动迁移 | 旧源码、配置、依赖、目标SDK | 全量盘点后再改；不以类名推断功能 |
| DLL/COM | DLL位数/框架、示例、依赖、线程模型 | 用 PE/项目元数据核对；未知时优先进程隔离 |
| HTTP | OpenAPI/接口文档、认证、错误模型 | 不用GET根路径猜健康 |
| 串口/TCP | 报文、帧边界、编码/校验、超时、状态字 | 未知帧边界时不能实现可靠读取 |
| 长任务 | 启动、运行、成功、失败、取消的可观察证据 | 没有成功证据就不能把Idle/Edit/Ready当成功 |

## 证据优先级

同一事实冲突时按以下顺序处理，并在交付中记录冲突：

1. 在目标版本真实设备上的录制报文与厂商API实际返回。
2. 厂商当前版本正式文档、类型库、头文件或反编译出的公开签名。
3. 厂商官方示例与已工作的当前驱动行为。
4. 旧驱动代码、日志和配置。
5. README、注释、文件名和经验推断。

低级证据不能静默覆盖高级证据。每项关键结论标记为：`confirmed`、`inferred`、`unknown`。只有 `confirmed` 可以定义安全相关动作和任务成功；`inferred` 必须有保守失败路径；`unknown` 进入待确认清单。

## 固定产物

编码前在工作记录或项目文档中建立四张表：

1. **能力映射**：来源入口 → Function/Operation/Get/Set/Nest/EnterExit → 参数/返回 → 状态。
2. **配置映射**：字段 → 类型 → 必填 → 默认值 → 密钥/敏感性 → YAML路径。
3. **通信映射**：连接名 → 传输/位数/线程模型 → 帧 → 超时/重试 → 并发/资源组。
4. **状态证据**：动作 → 接受证据 → 运行证据 → 成功/失败/取消证据 → 恢复策略。

已有驱动的每项状态只能是 `covered`、`missing`、`different`、`not-applicable` 或 `unknown`。不使用模糊的“基本完成”。

## 通信与隔离决策门

| 条件 | 选择 |
|---|---|
| 一条普通TCP/HTTP/Serial | 旧式单连接YAML，代码无连接样板 |
| 多条物理连接或事件通道 | `device.connections`，代码按键取连接 |
| 自定义网络/总线协议 | 注册 `ICommunicationProvider` |
| DLL与宿主位数、运行时、依赖、线程完全兼容 | 进程内DLL；厂商调用包进设备资源 |
| x86/net4x/COM/STA/消息泵/依赖冲突/稳定性未知 | `process` sidecar + LegacyAdapter |
| 文件交换 | `FileWorkflow` + 稳定检测 + 原子写 |

TCP、Serial、Modbus物理并发固定1。HTTP、process、DLL/API只有厂商明确支持时才能把 `maxConcurrency` 或 `deviceCallResources` 调大。`Parallelizability` 与 `FunctionalResources` 是上位业务能力，不是通信锁。

## 禁止猜测的内容

- 命令字、校验算法、字节序、单位换算和帧结束符。
- `Idle`、`Ready`、`Edit`、连接成功或void返回等同于任务成功。
- Nest名称暗示的机械臂可达性、存储/过渡角色、坐标和姿态。
- DLL可重入、线程安全、跨位数或跨运行时兼容。
- 非幂等命令在超时/断线后可安全重放。
