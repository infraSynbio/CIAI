## 审计输出格式

每项使用同一张表，保证差异可追踪：

| 来源位置 | 来源行为 | 目标位置 | 状态 | 证据/处理 |
|---|---|---|---|---|
| 文件:行号、文档页码或 API 名 | 外部可观察行为 | 文件:行号 | 已覆盖/缺失/不同/不适用 | 测试、报文或修改说明 |

不要只列类名或方法名。“名称存在”不等于参数、超时、命令、返回值和异常处理一致。

## SDK 契约

- [ ] 只有 7 个固定端点；路由和 HTTP 方法匹配。
- [ ] `Info` 注册包含 Function、Operation、Get、Set、Nest、EnterExit。
- [ ] 上位协议只发布一个 EnterExit；多个进/出动作由该入口参数分发，没有隐藏的第二个注解方法。
- [ ] 注解名称在各自类别内唯一，中文/英文标题和 FormJson 完整。
- [ ] 重复名称、错误方法签名和非法 FormJson 在启动阶段失败。
- [ ] Java/C# 模型序列化后的字段名、空值策略和状态码兼容。
- [ ] Function 快速接受、后台执行，并在启用时回调。
- [ ] Finish 保留 `instructionId`、`nestId`、completion、errorMsg、resultOutput。
- [ ] Java 早期驱动使用的 `ResultOutput.key/value` 访问器仍兼容；新增代码统一使用 `name/resultData`。
- [ ] 裸值与 `Result<T>` 的同步、Task/CompletableFuture 路径都保持成功/失败语义。
- [ ] Set 未知名称、裸 false 和 `Result.success(false)` 均不会静默成功。
- [ ] 已知端点错误方法返回 405，未知端点 404，参数错误 400，异常 500。

## 设备功能

- [ ] 原始 Function、Operation、Get、Set 数量和名称逐项覆盖。
- [ ] Nest 数量、ID、顺序、坐标、容量和 Enter/Exit 方法一致。
- [ ] 每个 Nest 的机械臂可达性、内部存储/过渡角色、来源/目的地、labware、坐标和姿态来自文档或用户输入，没有由SDK猜测。
- [ ] 型号可变或设备发现的 Nest 使用动态提供方法；固定 Nest 仍可使用注解。
- [ ] 参数类型、必填、默认值、单位、范围、枚举与表单一致。
- [ ] 命令顺序、条件分支、等待条件、完成判定和错误码一致。
- [ ] 急停、暂停、复位、恢复、初始化与关机行为有明确映射。
- [ ] 设备主动事件、报警和状态字段没有在迁移中丢失。
- [ ] 模拟模式覆盖成功、失败、忙碌和关键状态转换。

## 通信

### 通用

- [ ] 类型不会错误回退；DLL/TCP/HTTP/Serial 均有显式分支。
- [ ] 连接、断开、重连、取消、Dispose 和异常释放完成。
- [ ] 超时有单位且边界明确；不存在无限等待锁或后台线程。
- [ ] `FunctionalResources`、`Parallelizability`、传输事务锁和 DLL/API 调用资源没有混用。
- [ ] TCP/Serial 固定单通道请求-响应；DLL/API 的 `deviceCallResources` 由 YAML 配置并只包真实调用。
- [ ] 普通 TCP/Serial/HTTP 驱动无需构造函数、通信工厂或手写连接即可从 YAML 初始化。
- [ ] 单连接使用旧式最短配置；多物理连接使用命名 `connections`，默认连接明确。
- [ ] 相同底层总线/厂商会话使用一致的 `resourceGroup/maxConcurrency`；不同物理资源没有误共享。
- [ ] 自定义协议通过 Provider 注册，未知 type 启动失败，厂商 settings 未被封闭 schema 拒绝。

### TCP

- [ ] 原始字节、编码、字节序、长度头、帧边界和 CRC 一致。
- [ ] 粘包、拆包、半包、主动上报和断线均有测试。

### HTTP

- [ ] 需要的 GET/POST/PUT/DELETE 齐全。
- [ ] URL 拼接、Header、认证、超时、非 2xx 与业务错误分别验证。

### Serial

- [ ] port、baudRate、dataBits、stopBits、parity、timeout 映射到运行时串口。
- [ ] 发送使用协议要求的原始字节/终止符，不受系统换行符影响。
- [ ] 响应按明确的结束字节、固定长度或长度字段截帧。
- [ ] 多字节帧尾、缓冲区清理时机、编码和超时部分帧行为已验证。
- [ ] flowControl、DTR、RTS 与厂商文档一致。

### DLL/COM

- [ ] 平台目标、位数、运行库、搜索路径和部署文件齐全。
- [ ] 返回码、异常、回调委托生命周期和非托管资源释放正确。
- [ ] 无 SDK 通信对象时仍可初始化并得到正确心跳。
- [ ] x86/.NET Framework/COM/STA/消息泵依赖已选择进程桥接，或有同进程兼容证据。
- [ ] process适配器位数/运行时/工作目录/依赖文件正确；stdout无日志污染，stderr可观测，停机有界。

## 运行时

- [ ] 初始化失败使宿主启动失败。
- [ ] 心跳会反映未初始化、断连、设备错误、资源忙和正常状态。
- [ ] Function 资源等待有超时，释放位于 `finally`。
- [ ] callback.enabled=false 时完全不发送；true 时失败可观测且不崩溃。
- [ ] HTTPS 证书文件、信任根、指纹和 client-auth 配置实际参与验证。
- [ ] YAML 标准字段与自定义 settings 均传入驱动，没有二次读取配置。
- [ ] 必填厂商配置使用强类型必填读取并给出精确路径；未知厂商字段允许保留。
- [ ] 长任务检查取消状态并上报合理进度；事件监听和取消上下文在完成后释放。
- [ ] 文件型设备路径不能越过允许根目录，读取前等待稳定，输出使用原子替换。
- [ ] 环境变量替换、缺失变量失败和日志脱敏已验证。
- [ ] Function 队列有界、重复 instructionId 幂等、满载返回429；HTTP请求体和在途请求有上限。
- [ ] 停机在有限超时内等待请求、Function和回调，超时可观测。
- [ ] 日志不输出证书密码、Token、完整敏感样本或不必要的原始数据。

## 验证证据

- [ ] C# `DriverHost.ValidateConfiguration` 与 Java `DriverHost.validateConfiguration` 均可在无硬件、无端口监听时检查同一公共错误。
- [ ] 从非应用工作目录启动时，两端都能在驱动EXE/JAR旁找到配置，并以配置目录解析公共adapter和证书路径。
- [ ] `spec/ciai-driver-api.openapi.yaml` 只包含源码实现的7个端点，`spec/application.schema.json` 与当前公共YAML字段一致。

- [ ] SDK 所有目标框架构建为 0 错误；记录警告并判断是否可接受。
- [ ] 目标驱动和受影响旧驱动构建成功。
- [ ] 契约测试通过，覆盖 7 类注册、返回值、路由、配置、回调和心跳。
- [ ] 协议测试比较发送/接收的精确十六进制字节。
- [ ] TCP/Serial 并发请求测试证明一次发送及其响应不会被其他接口穿插。
- [ ] 命名连接测试覆盖默认选择、共享资源组并发、可选连接和初始化失败回滚。
- [ ] 动态 Nest 测试核对复杂位置角色，而不只核对数量。
- [ ] process桥接以假适配器验证精确长度前缀、异常退出和重新连接。
- [ ] 模拟服务实际启动并通过 HTTP 请求验证状态码与 JSON。
- [ ] 厂商 DLL/Java/证书/硬件缺失项明确列为“未验证”，不写成通过。
- [ ] git diff 只包含任务相关修改，并保留用户原有工作区改动。
