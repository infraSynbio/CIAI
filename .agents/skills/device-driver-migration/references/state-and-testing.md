# 状态机、错误与验证

## 长任务状态模型

每个长任务至少区分：

```text
NotStarted -> Accepted -> Running <-> Paused
                         |   |          |
                         |   +----------+
                         +-> Succeeded
                         +-> Failed
                         +-> Cancelling -> Cancelled
                         +-> Unknown
```

`Succeeded` 必须有厂商明确终态、与当前任务绑定的完成事件、结果文件或结果码之一。回到空闲但没有成功证据进入 `Unknown/Failed`，不能报 finish。

状态归并函数同时接收轮询与事件，必须：

- 绑定当前 `instructionId`、厂商任务ID或启动时间边界；忽略旧任务终态。
- 终态幂等，只完成一次；晚到事件不能把失败改为成功。
- 查询失败连续达到配置阈值后保守失败，单次瞬态失败可重试。
- 取消与急停分开：取消当前任务不等于设备安全急停。
- sidecar断线后只恢复查询；启动、开门、加样等非幂等请求不自动重放。

## 错误映射

保留四层信息：HTTP状态、CIAI `Result.code`、可读 `message`、厂商原始错误码/诊断。日志中保留关联ID，但遮蔽密码、Token、证书私钥、样本隐私数据和完整敏感报文。

配置错误在连接前报出YAML路径；协议错误包含命令/阶段与安全的十六进制摘要；设备拒绝、超时、断线、取消不能都压成同一“执行失败”。

## 无硬件测试矩阵

| 层 | 必测 |
|---|---|
| 编译 | SDK所有目标框架、目标驱动、sidecar目标位数/框架 |
| 声明契约 | 7端点、7类适用注解、重复名、签名、FormJson、Info JSON |
| 配置 | 示例实际解析、缺失必填项路径、HTTP默认启动、注释HTTPS不读环境变量 |
| 帧协议 | 黄金字节、拆包、粘包、多字节delimiter、超时、CRC/校验失败 |
| 并发 | TCP/Serial不交叉、共享resourceGroup、DLL/API预算、Function队列429 |
| 状态 | 成功、明确失败、空闲但无成功证据、暂停恢复、取消、旧事件 |
| 生命周期 | 初始化失败、重复初始化、断开清理、事件退订、优雅停机 |
| 资源许可 | 获取超时/中断不释放、每次成功获取只释放一次、异常路径不膨胀许可、实例间不误共享静态锁 |
| process | 真实子进程长度前缀、stderr日志、超时、崩溃、不可重放 |
| 安全 | 路径越界、请求体上限、秘密不进日志、HTTPS启用才要求证书 |

假设备必须模拟分段发送和连续帧，不能只调用解析函数。process 测试必须启动真实适配器进程，不能只直接调用适配器类。

## 有硬件验收

按“只读查询 → 连接/复位 → 可恢复动作 → 耗材动作 → 长任务 → 取消/急停”的风险顺序进行。记录设备型号、固件、厂商SDK版本、配置摘要、原始请求/响应摘要和结果。涉及机械动作前确认现场安全、耗材和人工观察条件。

## 完成判定

只有以下全部成立才可称为完成：

- 能力映射没有未解释的 `missing/different`。
- 配置示例可解析且预检通过；生产必填项有说明。
- 目标SDK、驱动和无硬件契约测试通过。
- 所有 `unknown` 已解决，或明确列为阻塞/未验证且不会被代码伪装成成功。
- 未使用真实设备时明确写“硬件未验证”，不把模拟结果外推为硬件兼容。
- 默认/显式构造路径都可创建，`functionalResources > 0`；覆盖初始化的驱动仍保持基类连接状态与失败清理语义。
